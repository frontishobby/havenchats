# babechat 남성향 언세이프 봇 분석 (2026-09-08)

API 로 인기 봇 14개 카드를 내려받고, 11개를 Gemini 3.8 Flash 로 총 23턴 플레이한 결과.
목적: Haven 이 가져올 시스템 + 캐릭터 출력의 공통 문법 추출.

## 0. 조사 방법 (재현용)

- 로그인: Playwright MCP Chrome 프로필(`~/Library/Caches/ms-playwright-mcp/mcp-chrome-a1ad007`)에 babechat 테스트 계정이 로그인돼 있음. 요청 헤더의 `authorization: Bearer <JWT>`(만료 ~10h) + `x-domain: babechat` 로 curl 가능.
- API base `https://api.babechatapi.com/ko/api/`:
  - 목록 `characters/top-active?gender=male&isSafetyEnabled=false`, `v2/characters?sort=popular&targetGender=male&isSafetyEnabled=false`, `characters/top-new?...`
  - 카드 `characters/:id` — `description`(스토어 소개), `details`(공개 설정 요약, 대부분 비공개/빈값), `initialAction`(오프닝 지문), `initialMessage`(첫 대사), `playGuide`, `startingScenarios[]`(복수 시작 상황), `replySuggestions`, `emotionImages`, `modelConfigs[]`, `recommendedModel`, `creatorKeywordBookLimit`, `systemPrompt: "custom_plus"`(실제 프롬프트는 비노출)
  - 방 생성 `POST message-room/:charId/false/:roomId` `{personaId, notebookId, startingScenarioId, useCreatorModelConfig}` (기존 방이면 이어짐)
  - 전송 `POST https://babechatapi.com/ko/api/u/message/:charId` body `{prompt, roomId, proChatCount:1, isMultipleImage:true, model, outputLanguage, impersonation, memoryLimit:5, outputLevel:1, thinkingLevel:"mid", redo, enablePass}` → **Vercel AI SDK UI message stream**(`x-vercel-ai-ui-message-stream: v1`, `data: {"type":"text-delta"}`) — 우리와 같은 SDK.
  - 히스토리 `v2/messages/:charId/false/:roomId?order=asc&limit=500`, 요약 `messages/:charId/false/:roomId/memory` (`autoSummarize`), 재생성 후보 `message-variants/:msgId`
- 과금: 무료 포인트 11,515 → 9,545 (23턴, 3.8 Flash ≈ 85~100p/턴). proCount 는 0 이었음.
- 스트림은 항상 `# Response\n` 로 시작하고 저장 시 이 헤더가 제거됨 → 플랫폼 시스템 템플릿이 `# Thinking`(숨김) / `# Response` 식 섹션 출력을 강제하는 것으로 추정.

## 2. 캐릭터 출력 공통 문법 (11개 봇, 23턴 실측)

거의 모든 봇이 아래 순서를 따른다. **[표정 이미지] → 지문 → `이름 | "대사"` → … → 상태창 코드블록**.

1. **대사 라벨**: `이름|"대사"`, `"**이름 |** 대사"`, `이름 | 대사` 세 변형이 있고 전부 `|` 구분자. Haven 의 `발화자 | "대사"` 규칙과 동일 → 렌더러 호환.
2. **지문**: 3인칭 현재/과거 산문. `*…*` 기울임을 쓰는 봇(이세계·너도똑같을거잖아)과 안 쓰는 봇이 반반. 감각 묘사(냄새·소리·질감) 밀도가 높고, 분량은 700~2,500자/턴(평균 ~1,300자, outputLevel 1).
3. **표정·장면 이미지 인라인**: 턴당 2~7장(평균 3.6장). 대사 직전에 그 인물 표정 이미지를 넣는 패턴이 지배적. 코드는 `캐릭터코드+상황코드`(예 `F1_2`, `SN6`) 평면 코드표이며 상황코드가 20~86개(표정 8~10 + 일상 10 + 성행위 40~60). GIF(움짤)도 사용.
4. **매 턴 상태창** (11/11): 공통 필드는 ⏳시간·날짜(가상 시계가 턴마다 2~3분씩 진행) / 📍장소 / 유저 상태 / **인물별 [이름: 호감도(이모지+수치) | 감정 | 복장 | 현재 행동]** / 💬 속마음 한 줄 / 🧭 루트·모드·이벤트 표기 / 🗒️ 일정·목표 / 🎒 인벤토리. 형식은 봇마다 다르지만(```INFO, ```stat v1, 표 없는 이모지 라인, SVG 이미지) 의미 구조는 같다.
5. **선택지**: 절반 이상이 상태창 끝에 `[1. …] [2. …] [3. …]` 또는 SVG `c1~c4` 로 다음 행동 1~4개 제시. 유저는 번호만 입력해도 진행.
6. **속마음 노출**: 러브돌 봇은 `--- **'속마음'** ---` 블록을 지문 사이에 끼움, 다른 봇은 상태창 💬/💭. `!하라구로`(겉속 다름) 모드가 이걸 켬.
7. **해설자(나레이터) 페르소나**: 메이드 하렘은 2인칭 "어머나❤ 범준님…" 해설자가 유저에게 말을 걸고 `!음소거` 로 끔. 제국과 정복자는 "~답니다/~어요" 동화체. 해설자 톤 자체가 캐릭터의 셀링 포인트.
8. **모드 반영**: `!천박 !냄새` 입력 후 상태창에 `🎭!천박 !냄새` 로 표시되고 다음 턴부터 어휘·시점이 바뀜(냄새 묘사 집중, 저급 어휘). 모드 = 프롬프트 안 조건부 지침.
9. **판정/RPG**: 이세계 봇은 `![d20](…?val=3&act=육체적_압박&mod=0)` 주사위 이미지를 응답 첫 줄에 두고, val 이 낮으면 유저 행동을 **실패로 서술**(손목 잡기 → 뿌리침 → 어부들에게 몰림). 능력치·HP/MP·랭크·레벨 필드 포함. (주사위 값은 모델이 지어내는 가짜 난수.)
10. **유저 페르소나 강반영**: 계정 소개 "20cm 거근 보유" 가 성행위 장면에서 "20cm 흉기" 로 그대로 쓰임. 이름(범준)도 상태창 👤 에 박힘.
11. **NSFW 어휘**: 3.8 Flash 에서 삽입·사정 직접어(보짓구멍, 자지, 질싸), 의성어(푸욱, 찌그드득), ❤/💕 이모지, 'ッ' 표기까지 거부 없이 출력. 23턴 중 거부·필터 0회. 기본 모드도 노골적이며 `!천박` 은 어휘 급을 한 단계 더 낮춤.
12. **강한 캐릭터 톤**: 남성향 언세이프 봇은 반말·욕설(씨발, 새끼, 찐따)이 기본. 첫 턴부터 유저를 깔보는 NPC(로건·세미, 이시혁, 유하민)로 갈등을 세우고 유저가 뒤집는 구조(NTL/역전).
13. **빠른 사건 진행**: 한 턴에 신벌→추방→해안가 도착처럼 장면을 크게 전환하고, 턴 끝은 항상 유저에게 공을 넘기는 질문·선택지·클리프행어.
14. **오프닝 안 숨은 지시**: `![](<상태창의 루트 항목에 'MAIN' 표기>)`, `![](<이미지 3장이상 출력할것>)`, `[//]: # (유하민행동지침…)` 처럼 **렌더되지 않는 마크다운**에 모델용 지시를 숨겨 오프닝을 프롬프트로 활용.
15. **다인 군상극**: 인물 3~67명, 한 턴에 4~5명이 각자 대사·표정 이미지·상태 행을 가짐. 상태창이 이걸 추적하는 장치.
16. 대필(impersonation) 출력은 유저 대사를 `"…"` 큰따옴표만으로(라벨 없이) 쓰고 이어서 NPC 반응 + 상태창까지 한 응답에 넣음.

## 3. Haven 에 가져올 것 (우선순위)

1. **표준 상태창 블록 + 카드 렌더러.** 응답 끝 ```INFO 블록을 제작자 옵션으로 켜고(필드: 시간/장소/인물별 호감도·감정·복장·행동·속마음/모드/목표/선택지), 클라가 파싱해 babechat SVG 같은 카드로 그린다. 파싱 실패 시 코드블록 그대로. 복장 원장(`outfits`)·실시간 이미지 프롬프트와 필드를 공유하면 일석이조.
2. **응답 내 선택지 → 클릭 입력.** 상태창의 `[1. …]` 를 칩으로 렌더, 클릭 시 입력창 채움(기존 입력 제안 칩 재사용). 별도 LLM 호출 없이 매 턴 제공되므로 비용 0.
3. **제작자 명령어/모드 정의.** 캐릭터 폼에 `{이름, 설명, 프롬프트 효과}` 목록 → 채팅 헤더 칩으로 토글, 활성 모드는 system 꼬리 블록(모듈처럼 prefix 캐시 무영향) + 상태창 표기. `!커스텀 (규칙)` 류 자유 입력 모드도 허용.
4. **시나리오별 플레이 가이드·추천답변.** greetings 항목에 `title / guide / suggestions[]` 추가, 오프닝 화면에 가이드 카드 + 시작 칩.
5. **유저노트(세션 노트).** 세션별 자유 텍스트를 system 끝(요약 블록 옆)에 주입. 요약 모달에 탭으로 붙이면 UI 비용 최소.
6. **진짜 주사위.** 제작자 옵션 '판정 모드': 서버가 유저 메시지 끝에 `[Roll d20=7]` 을 실제 난수로 부착하고 지침에 성공/실패 서술 규칙을 넣음. babechat 은 가짜 난수라 차별점.
7. **속마음 블록 렌더.** `💭` 또는 `> 속마음:` 을 별도 스타일(흐린 박스)로.
8. **로어북(키워드 트리거).** 제작자 항목 `{keywords[], content}` → 최근 N턴 텍스트 매칭 시 system 꼬리에 삽입. 캐시 영향 적음.
9. **대필 옵션.** 이어가기(») 롱프레스/옵션으로 '내 행동까지 써서 진행' (impersonation).
10. **`# Thinking / # Response` 스캐폴드 실험.** babechat 은 모든 응답에 이 구조를 강제하고 Thinking 을 서버가 벗김. Flash 급 모델에서 상태창 일관성이 좋은 이유일 수 있으니 A/B 해볼 가치. 우리 구조에선 스트림 파서가 `# Response` 이전 텍스트를 버리면 됨.
11. **표정 이미지 코드표 규모.** 인기 봇은 인물당 상황코드 20~86개(성행위 40+). 우리 축×조합에서 '상황' 축 값 26개 초과 시 두 글자 코드는 이미 지원하므로, 제작 폼에 babechat 식 표준 상황 목록 프리셋(표정 10·일상 10·성행위 40)을 제공하면 대량 업로드가 쉬워짐.
